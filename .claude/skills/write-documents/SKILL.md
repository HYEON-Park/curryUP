# 자기소개서·경력기술서 작성 배치 (Claude 직접 실행)

## 실행 시점 (트리거 규칙)

- **scrape 배치(매일 08:00) 이후 신규 공고가 있으면 반드시 실행한다.**
- 실행 대상:
  1. 신규 수집 공고
  2. 즐겨찾기 공고 — 문서 작성 내역 확인 후, 아직 작성되지 않은 것만
- 사용자가 "문서 작성 배치", "다음 배치 진행" 등을 요청할 때도 실행한다.

## 문서생성 기준 (대상 선정 규칙)

아래 두 조건 중 하나를 만족하는 공고만 문서를 생성한다.

1. **신규 공고 트랙**: 다음 세 가지를 모두 만족
   - 오늘 신규 수집된 공고 (`collectedAt`이 오늘)
   - 기업 평점(rating) **2.8 이상** (평점 없음은 제외)
   - 사용자와의 **매칭률 70% 이상** — §6-1 매칭률 사전 평가표의 '종합 매칭률'로 판단.
     평가표까지 작성한 결과 70% 미만이면 해당 공고의 문서 생성을 생략하고,
     공고명·매칭률·생략 사유를 실행 보고에 포함한다 (documents는 null 유지)
2. **즐겨찾기 트랙**: 즐겨찾기(isFavorite) 지정된 공고 — 평점·매칭률 조건 없이 항상 생성

공통 필터:

- **연차 필터**: 공고 요구 연차(requiredYears.min)가 프로필 연차 ±2를 벗어나면 작성 대상에서 제외하고,
  해당 공고를 삭제 후보로 사용자에게 보고한다. (예: 프로필 연차 N년 → 요구 N+3년 이상 공고는 제외·삭제 제안)
- **이미 자소서가 있는 공고(`documents.coverLetter`가 채워진 공고)는 건너뛴다.**
  단, `documents`가 있어도 `coverLetter`가 빈 문자열/없음이면(매칭률 조회 배치가 `documents.matchReport`만
  먼저 채운 경우) 아직 자소서 미작성이므로 **작성 대상에 포함**한다.

## 실행 절차

1. `backend/src/data/jobPostings.json`에서 **아직 자소서가 없는 공고**(`documents`가 null이거나 `documents.coverLetter`가 빈 문자열/없음) 중 대상 선정
   - 기본 대상: 위 **문서생성 기준** 적용 (신규+평점 2.8↑+매칭률 70%↑ or 즐겨찾기)
   - `documents.matchReport`가 이미 있으면(매칭률 조회 배치가 먼저 작성) **그 매칭률을 재사용**해 70% 판정에 쓰고 matchReport는 다시 만들지 않는다. 없으면 매칭률 평가표부터 새로 작성한다.
   - 사용자가 범위를 지정하면 그에 따름
2. `backend/src/data/userProfile.json`에서 프로필 로드 (아래 §8의 필드 매핑대로 로드하며, 개인 정보는 이 문서에 하드코딩하지 않는다)
3. 공고별로 아래 프롬프트 체계에 따라 4개 필드 생성:
   - `matchReport` — 매칭률 사전 평가표 + 지원 권장도 (§6-1, §6-2)
   - `workExperience` — 공고 맞춤 경력기술서 (§6-3)
   - `coverLetter` — 자기소개서: 지원동기(KKK) + 직무 역량(STAR-F) + 입사 후 포부 (§6-4)
   - `intro` — 자기소개 요약 (2,000자 미만)
4. 인간화 리라이팅(§3) 적용 후 자가 검증 체크리스트(§7) 통과 확인
5. `generatedAt`에 ISO 시각 기록 후 jobPostings.json에 id 기준으로 병합 저장
   - 저장 직전에 파일을 다시 읽어 최신 상태에 병합할 것 (서버가 파일을 동시에 쓸 수 있음)
6. 완료 후 작성 건수·회사 목록 보고

주의: 같은 회사의 중복 공고(URL만 다름)는 내용을 재활용하되 공고별 요구사항 차이만 반영한다.

## 프롬프트 체계

당신은 한국 IT 업계의 자기소개서·경력기술서 작성 전문가입니다.

### 0. 기본 작성 원칙 (기존 persona 규칙)

1. 추상보다 구체. 모든 주장은 실제 업무 장면·산출물·수치로 뒷받침
2. 갭(Gap) 정직 처리. 보유하지 않은 기술·경험을 창작하지 않고, 학습 의지 또는 유사 패턴 적용으로 보완
3. 회사 분석 기반. 일반론 금지. 해당 회사의 사업 단계·제품·확장 방향과 연결
4. 능동태 우선. 수동태·명사형 표현 자제
5. **사실관계 유지. 없는 경력·거짓 경력·없는 데이터를 만들지 말 것**

### 1. 전략 프레임워크

#### 1-1. KKK 전략 (지원동기 문항용)

"산업 → 회사 → 본인" 3단 구조로 전개

| 단계 | 설명 |
|---|---|
| K1: 산업 (Industry) | 지원 회사가 속한 산업의 흐름·전환점·본질을 정의 |
| K2: 회사 (Company) | 그 산업 안에서 해당 회사의 위치·최근 방향성·사업 단계 분석 |
| K3: 본인 (Kandidate) | 본인의 경험이 왜 그 회사의 그 자리에 맞는지 매칭 근거 제시 |

#### 1-2. STAR-F 전략 (직무 역량·문제 해결 문항용)

| 단계 | 내용 |
|---|---|
| S (Situation) | 상황·배경 (구체적 프로젝트, 기간, 규모) |
| T (Task) | 과제·목표 (해결해야 할 문제) |
| A (Action) | 실제 행동 — 능동태 동사 3개 이상 사용 |
| R (Result) | 결과 — 수치 필수 |
| F (Future) | 지원 회사에서 이 경험이 어떻게 적용 가능한지 |

### 2. 필수 반영 규칙

#### 2-1. 지원 회사 분석 방식

- 회사 사업·제품·인재상·최근 방향성을 검색 후 반영
- 회사가 자체 발행한 콘텐츠·보도자료 인용
- 공고 본문의 특정 문장 직접 인용 → "이 문장을 읽으면서 멈췄습니다" 톤
- **정보 부족 시 추측 금지, 공고 시그널만 사용**

#### 2-2. 매칭 분석 원칙

- 공고의 담당업무·자격요건·우대사항을 분해해 핵심 역량 3~5개 정의
- 매칭도를 **강/중/약/없음** 4단계로 자체 평가
- 갭(Gap)은 숨기지 않고 솔직히 인정
- 갭 위에서 학습 의지·유사 패턴 적용·대체 경험으로 보완 전략 명시

#### 2-3. 수치화 원칙

- 모든 결과는 수치로 표현 (수치 없으면 추정치라도 표기 후 "실데이터로 교체 권장" 안내)
- 대표 수치 세트: `userProfile.json`의 `representativeMetrics`에 값이 있으면 그 수치를 재사용한다.
  없으면 공고·경력기술(careerHistory) 기반 추정치로 표기하고 "실데이터로 교체 권장"을 붙인다.

#### 2-4. 소제목 규칙

- 문단마다 [대괄호] 형식 소제목 배치
- 인사담당자의 5초 스캔에 대응

### 3. 인간화 리라이팅 규칙 (30세 한국인 취준생 말투)

#### 3-1. 문장 리듬 규칙

- 문장 길이를 극단적으로 다양화 (긴 문장과 짧은 문장 교차)
- 전체 문장의 30% 이상을 15자 이내 단문으로 배치
- 문단 끝을 "~하겠습니다"로 단조롭게 닫지 말고 단언·제안·사실 진술 등 다양화

#### 3-2. 금지 표현 (AI 빈출 단어 · 자기소개서 클리셰)

금지 단어:
- 열정, 혁신, 시너지, 임팩트, 패러다임
- 지속가능한, 탁월한, 유연한, 선도하는
- 트렌드, 매료된, 깊은 인상

금지 클리셰:
- "~한 경험을 통해 ~를 배웠습니다"
- "~에 매료되어"
- "~에 깊은 인상을 받아"
- 추상적 형용사 나열

#### 3-3. 톤 규칙

- 30세 한국인 취준생 말투 (자연스러운 구어체)
- 겸손하지도 건방지지도 않은 톤
- `(n)`년차 경력자의 담담한 자기 선언 톤 — `(n)` = `userProfile.json`의 `yearsOfExperience`

### 4. 강조 원칙

#### 4-1. 인사담당자 관점 필수 반영

- 인사담당자는 첫 5초에 이력서를 스캔
- "이 사람이 우리 공고에 매칭되는가"
- "무엇을 만들어본 사람인가" (산출물 단위)
- "누구와 일해본 사람인가" (협업 구조)

#### 4-2. 문장 구체화 원칙

| 원문 | 리라이팅 |
|---|---|
| "커뮤니케이션했다" | "명세 협의·연동 테스트했다" |
| "운영 및 유지보수했다" | "운영자 편의 자동화 기능 개발했다" |
| "다수 수행" (모호) | "3건 이상 / 월 30건대" (구체 수치) |
| "생각합니다 / 인지합니다" | "다뤄왔습니다 / 만들어왔습니다" |
| "공부하고 있습니다" | "강점입니다 / 무기입니다" |

#### 4-3. 마무리 원칙

- 마지막 문단은 입사 후 기여 방향으로 마무리
- 신뢰감 있고 담담한 톤으로 종결

### 5. 시그니처 표현 (본인만의 자산)

모두 `userProfile.json`에서 로드한다. 값이 없으면 해당 항목은 생략한다(빈 값을 지어내지 말 것).

#### 5-1. 대표 슬로건 → `userProfile.slogan`

- 값이 있으면 자기소개서·경력기술서·소개에 반복 배치하고, **원문 그대로 유지·변형 금지, 문서당 최소 1회 등장**한다.
- 값이 없으면 슬로건 삽입·자가검증(§7 슬로건 항목)을 건너뛴다.

#### 5-2. 커리어 서사 → `userProfile.careerNarrative`

- 값이 있으면 지원 회사(특히 방향성이 맞는 회사)에 이 서사를 이식해 일관성을 유지한다.
- 값이 없으면 `careerHistory`에서 자연스러운 서사를 도출한다.

#### 5-3. AI 도구 활용 어필 → `userProfile.aiToolUsage`

- 값이 있으면 직무 역량·개인 프로젝트 맥락에서 활용 경험을 어필한다. 없으면 생략한다.

### 6. 작성 순서 (기본 템플릿)

각 항목이 저장될 필드를 명시한다.

#### 6-1 + 6-2. 매칭률 사전 평가 + 지원 권장도 → `matchReport` 필드

```
1) 매칭률 사전 평가 (표 형식)
   - 필수 자격요건 매칭
   - 스택 매칭
   - 담당업무 매칭
   - 우대사항 매칭
   - 종합 매칭률 (%)
   - 강점 Top 3
   - 갭 Top 3~5

2) 지원 권장도 및 다른 공고와의 비교
```

#### 6-3. 경력기술서 (공고 맞춤 리라이팅) → `workExperience` 필드

```
   - 핵심 역량
   - 담당 업무
   - 경력 기술 (프로젝트 순서를 공고 관련성 순으로 재배치)
   - 자격 사항
   - 개인 프로젝트 / 학습
```

#### 6-4. 자기소개서 → `coverLetter` 필드

```
   4-1) 지원동기 (KKK 분석형)
   4-2) 직무 역량 (STAR-F 분석형)
   4-3) 입사 후 포부 (3단계 구조)
```

#### 6-5. 인간화 리라이팅

- 지원동기·직무 역량·입사 후 포부 각각을
  30세 취준생 말투 + 단문 30%+ + AI 단어 제거로 재작성한 최종본만 저장

#### 6-6. 사용 시 체크포인트 (matchReport 말미에 포함)

- 수치 검수 필수
- 회사별 사전 학습 권장
- GitHub 정리 권장
- 면접 대비 시나리오
- 이력서·자기소개서 함께 제출 여부

### 7. 자가 검증 체크리스트

응답 최종본 도출 전 다음 항목 자체 확인:

- [ ] AI 빈출 단어 0회
- [ ] 회사명·제품명·사업 영역 본문에 최소 2회 등장
- [ ] 수치 또는 구체 산출물 최소 3개 포함
- [ ] 갭이 있는 경우 숨기지 않고 솔직히 인정 + 보완 전략 명시
- [ ] 문단마다 소제목 존재
- [ ] 마지막 문단은 입사 후 기여 방향으로 마무리
- [ ] 인간화 리라이팅 시 단문 30%+ 준수
- [ ] `userProfile.slogan`이 설정돼 있으면 시그니처 슬로건이 최소 1회 등장 (없으면 이 항목 제외)

### 8. 개인 프로필 (하드코딩 금지 — 전부 `userProfile.json`에서 로드)

개인 정보는 이 문서에 박아두지 않는다. 매 실행 시 `backend/src/data/userProfile.json`에서 읽어 사용한다.

| 항목 | 프로필 필드 |
|---|---|
| 경력 연차 (`(n)`) | `yearsOfExperience` |
| 기술 스택 | `skills` |
| 경력 기술(도메인·주요 프로젝트 포함) | `careerHistory` |
| 자격 | `certifications` |
| 근무지 | `locations` |
| 희망 직무 | `desiredRoleCategories` / `roleAnswers` |
| 개인 프로젝트 / 학습 | `sideProjects` / `learningStack` |
| AI 도구 활용 | `aiToolUsage` |
| 대표 슬로건 | `slogan` |
| 커리어 서사 | `careerNarrative` |
| 학력 | `education` |
| 커리어 방향성 | `careerDirection` |
| 관심 도메인 | `interestDomains` |
| 대표 수치 세트 | `representativeMetrics` |

비어 있는 필드는 해당 규칙을 건너뛴다(없는 경력·데이터를 지어내지 말 것 — §0-5).

### 9. 회사 유형별 톤 조정 (방법론)

공고의 회사 유형을 먼저 분류한 뒤 톤을 맞춘다. 아래는 유형별 방향 예시다(회사명은 예시일 뿐, 공고마다 판단).

| 회사 유형 | 톤 |
|---|---|
| SI/금융 IT 정통파 | 신뢰감 있는 담담한 톤 |
| 커머스 스타트업 | 실행 중심의 단단한 톤 |
| 딥테크 스타트업 | 도메인 존중 + R&D 학습 태도 |
| 자체 솔루션 회사 | `careerNarrative`(있으면)를 이식 |
